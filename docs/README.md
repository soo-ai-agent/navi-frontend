# navi 설계 문서

서버가 질문을 하나씩 내려주고, 클라이언트가 답을 보내고, 더 물을 것이 없어지면 서버가 적금 순위를 내려주는 구조다.

## 공통 전제

네 문서 모두에 적용된다.

- 서버는 **무상태(stateless)** 다. 사용자 답변을 저장하지 않고, 매 요청에 실려 온 답 전체로 그때그때 계산한다.
- 답의 원본은 브라우저 sessionStorage(`common/services/recommendationService`)에 있다. 세션 id·쿠키·회원 개념은 없다.
- 순위 계산에 AI 를 쓰지 않는다. AI 는 공시 원문을 데이터로 번역하는 오프라인 작업에만 쓴다.

## 엔드포인트 셋

사용자 화면이 쓰는 것은 이 셋뿐이다.

| 엔드포인트 | 무엇을 하나 | 설명 |
|---|---|---|
| `POST /api/v1/questions/next` | 답 전체를 받아 다음 질문 또는 최종 순위를 준다 | [질문 API 계약](question-api.md) |
| `GET /api/v1/products` | 공시된 전체 적금 목록 | [적금 데이터](savings-data.md) |
| `POST /api/v1/products/compare` | 납입액·기간으로 상품별 적용금리와 만기금액을 계산한다 | [적금 데이터](savings-data.md) |

## 문서 넷

위에서부터 순서대로 읽으면 전체가 이어진다.

| 문서 | 무엇을 담나 | 이럴 때 읽는다 |
|---|---|---|
| [질문 API 계약](question-api.md) | 왕복 형식 · 예시 JSON · 타입 · 답의 수명 | 클라이언트를 만들거나 API 를 붙일 때 |
| [순위 엔진](ranking-engine.md) | 서버가 매 턴 하는 일 (판정 → 순위 → 질문 선별) | 서버 계산 로직을 구현·이해할 때 |
| [적금 데이터](savings-data.md) | 공시 원본 정제 규칙과 응답 모양 | 데이터 수집·가공을 만들 때 |
| [AI 의 역할](ai-role.md) | AI 를 쓰는 자리와 쓰지 않는 자리 | AI 파이프라인을 설계할 때 |

## 한눈에 보는 전체 구조

```
[한 달에 한 번, 미리]                      [사용자가 쓸 때마다]
공시 수집 → AI 번역 → 검수 → 적금 데이터    답 전체 → 규칙 엔진 → 다음 질문 or 최종 순위
(적금 데이터 · AI 의 역할)                 (질문 API · 순위 엔진)
```
